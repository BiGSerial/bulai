# Instruções de deploy — release de 06/11/2026 (experiência nativa, conversa com contexto, tolerância a erros, landing page)

Leia junto com `docs/deployment/kinghost.md` (procedimento completo) e `docs/deployment/release-2026-11-05.md` (release anterior, que exigiu reinstalar o conjunto confiável e novas variáveis). Aqui está **só o que muda nesta release**.

## 1. Precisa rebuildar? Sim, só as imagens

| O quê | Por quê | Como |
| --- | --- | --- |
| Imagens `bulai-app` e `bulai-web` | Código novo (telas do paciente e do admin, programação dinâmica, serviços, JS/CSS compilados, service worker `bulai-static-v5`, manifesto) | Automático no workflow *Deploy (KingHost)* → ação `deploy` com o SHA do merge na `main` com CI verde. |
| Banco | Migrações `2026_11_06_011348_add_trigram_search_to_catalog` (`CREATE EXTENSION IF NOT EXISTS pg_trgm` + 5 índices GIN de trigramas no catálogo) e `2026_11_06_015003_add_dynamic_interval_to_patient_medications` (duas colunas aditivas em `patient_medications`: `interval_minutes`, `schedule_mode`; remédios já cadastrados ficam em `fixed`, sem mudança de comportamento) | Roda sozinha no `activate` (`php artisan migrate --force`). A extensão vem na imagem `pgvector/pgvector:pg17` já em uso; a migração roda como o papel `bulai`: se o PostgreSQL recusar `CREATE EXTENSION` por permissão, crie antes como superusuário (seção 3). Os índices sobre ~39 mil registros levam poucos segundos. |

**Não muda**: `compose.prod.yaml`, scripts de deploy, conjunto confiável (`/opt/bulai/trusted`), modelos, `app.env` (nenhuma variável nova). Não é preciso entrar na VPS antes do deploy, salvo a verificação opcional da seção 3.

## 2. Ordem de execução

1. **Merge da PR** na `main` com CI verde; anote o SHA completo.
2. **GitHub → Actions → Deploy (KingHost) → `deploy` + SHA**. O `activate` faz `pg_dump`, aplica a migração e troca as imagens.
3. **Pós-deploy** (na VPS, como administrador, ou pela interface):
   - `sudo bulai-deploy status` → todos os serviços saudáveis.
   - `sudo bulai-deploy artisan tinker --execute 'echo count(app(App\Services\Interactions\FuzzyMedicineMatcher::class)->match("losartam"));'` → número maior que zero confirma a extensão e os índices.
   - No celular: abrir `https://<domínio>/` (landing), entrar, conferir a Início (cartão do dia, cartão "Instalar o aplicativo" no Chrome Android após alguns acessos), `/perguntar` (ditar e perguntar "posso tomar lozartana com omeprasol?"), `/hoje`, `/perfil`.
   - Usuários com o app já instalado recebem a faixa "Há uma versão nova" → Atualizar (service worker v5).

## 3. Se a migração falhar em `CREATE EXTENSION`

```bash
sudo docker exec -it bulai-postgres-1 sh -c 'psql -U "$POSTGRES_USER" -d bulai -c "CREATE EXTENSION IF NOT EXISTS pg_trgm;"'
sudo bulai-deploy artisan migrate --force
```

A migração é idempotente (`IF NOT EXISTS` em tudo). A segunda migração (colunas) não depende da extensão.

## 4. Rollback

`Actions → rollback` reaplica as imagens anteriores. A extensão, os índices e as duas colunas novas podem ficar: o código anterior não os usa e eles não alteram dados.
